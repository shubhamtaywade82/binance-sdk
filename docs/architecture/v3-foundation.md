# v3 Architecture — Foundation (Milestone 1)

Status: implemented in `3.0.0-next.1` · branch `feat/sdk-v3-core`

## The principle

> Generated code owns Binance protocol fidelity. Handwritten code owns developer
> ergonomics, trading semantics, state, risk, execution, and AI.

The v3 rewrite is a controlled platform migration, not a feature-by-feature
expansion. Existing investments (HttpClient, signing, rate-limit tracking,
time sync, execution reconciliation, risk gateway, paper backend, tools, MCP)
are preserved; the underlying architecture changes.

## Layer map

```
Binance Specifications
        │
        ▼
Contract / Generator            contracts/  (machine-readable catalogs)
        │
        ▼
Binance Core                    src/core/   (context, credentials, transport,
        │                                    events, decimal, json)
        ▼
Product Clients                 src/products/{usdm,spot,coinm}/...
        │
        ▼
Domain / State / Execution      src/state/ src/execution/ src/risk/ src/paper/
        │
        ▼
Agent surface                   src/tools/ src/mcp/ skills/
```

## Milestone 1 deliverables

| Piece | Location | Notes |
|---|---|---|
| `CoreContext` | `src/core/context.ts` | Shared runtime: 6 lazily-built cached per-host HttpClients, credentials, events, policy, transport config. Public as `client.core`. |
| `Credentials` | `src/core/credentials.ts` | Value object: `canSign`, `hasApiKey`, `describe()`, HttpClient-parity algorithm inference. |
| Product boundary | `src/products/types.ts` | `ProductClient` = product id + core + close. |
| USDⓈ-M adapter | `src/products/usdm/` | `USDMClient` (standalone, caller-supplied context) + `buildUsdmSurface` (single construction path shared with the facade). |
| Contract catalogs | `contracts/` | `catalog.json`, `endpoint-catalog.json` (220 ops), `security-catalog.json`; generated by `npm run contracts:generate`, CI-validated against the registry. |
| Lazy facade | `src/client/BinanceClient.ts` | Constructor builds only the core; namespaces build on first access, cached with stable identity. |
| Compat facade | same | `client.futures` (USDⓈ-M + `.usdm`/`.coinm` aliases) unchanged; all v2.x surfaces identical. |

## Migration order (strangler)

USD-M → Spot → COIN-M → Margin → Options → Portfolio Margin → …

USDⓈ-M is first (strongest product). Each product moves onto
`build<Product>Surface(core)` + a standalone `<Product>Client`, sharing one
wiring between facade and standalone entry points.
